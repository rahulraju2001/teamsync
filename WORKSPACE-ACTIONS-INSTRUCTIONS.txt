TeamSync workspace actions update

Replace these four files in your existing project with the matching files in this archive:
- server/src/routes/workspaceRoutes.js
- server/src/middleware/auth.js
- src/context/WorkspaceContext.jsx
- src/components/layout/Sidebar.jsx

No new npm dependencies or database migration are required.

Behavior added:
- Non-owner members can leave the active workspace, and the remaining members receive a live membership refresh.
- A non-owner Administrator cannot leave if they are the last Administrator.
- Workspace owners cannot leave; the UI explains that ownership must be transferred first.
- Only the workspace owner can delete the workspace.
- Deleting a workspace removes its projects, their tasks (including embedded comments), and workspace notifications. Invitations are embedded in the workspace document and are removed with it.
- Users affected by a leave/delete are moved to another workspace if they belong to one. Otherwise, a new personal workspace is created so they can continue using TeamSync.
- The workspace actions use a styled confirmation modal.

Important limitation:
The current project does not yet include an ownership-transfer feature. Therefore, an owner is blocked from leaving until that separate feature is implemented; owners can still delete their workspace.

After replacing the files:
1. Restart the backend and frontend development servers.
2. Test with at least two accounts.
3. Test that a non-owner can leave, the owner cannot leave, only the owner can delete, and deleting a workspace removes its associated projects/tasks/notifications.

This archive intentionally excludes .env files, .git, node_modules, and package-lock files. Keep your existing environment files and Git history.
