PROJECT DETAILS DIRECT-REFRESH FIX

Problem:
Refreshing a URL such as /projects/:projectId caused ProjectDetails to access
project.status before workspace projects had finished loading. On the initial
render, project was undefined because the projects array was still empty.

Changes:
- Made the project overdue calculation safe while project data is unavailable.
- Added a loading state while workspace data is being fetched.
- Added a friendly data-loading error state with retry and back navigation.
- Kept the Project not found state for after loading has completed and the
  requested project genuinely is not available.

Test:
1. Sign in and open an existing project.
2. Refresh the browser while on /projects/:projectId.
3. The page should briefly show "Loading project..." and then render the project.
4. Open a non-existent project ID after loading; it should show "Project not found"
   rather than crashing.
