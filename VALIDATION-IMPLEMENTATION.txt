TeamSync - Backend Validation Update

Implemented in this update

1. Reusable backend validation
   - Added server/src/middleware/validate.js.
   - Validates JSON object bodies, required fields, types, string lengths,
     allowed enum values, date-only values, MongoDB ObjectIds, and route IDs.
   - Rejects unknown fields in project/task create and update requests.

2. Consistent error responses
   - Mongoose ValidationError and CastError now return HTTP 400.
   - Duplicate-key errors return HTTP 409.
   - Malformed JSON returns HTTP 400.
   - Oversized JSON returns HTTP 413.
   - Production 500 responses no longer expose internal error messages.

3. Authentication input validation
   - Registration validates name, email, password and optional invitation token.
   - Login validates email and password before querying MongoDB.
   - Email is normalized to lowercase; names are trimmed.
   - Passwords are not trimmed. Registration enforces 8+ characters and a
     72-byte UTF-8 maximum to avoid bcrypt's 72-byte input truncation.
   - Basic in-memory limits are applied: 5 registrations per IP per hour and
     10 login attempts per IP per 15 minutes.

4. Project/task validation
   - Project create/update validates name, description, status and deadline.
   - Task create/update validates title, description, status, priority,
     due date, project ID and assignee ID.
   - Assignees must still be members of the active workspace.
   - Task due dates remain constrained by the project's deadline.
   - Task comments are validated for type, required content and length.

Not included

- No Helmet, CORS changes, request-size changes, external rate-limiting
  package, refresh-token flow, or other security middleware changes were made.
- The small in-memory rate limiter is intended for this single-instance
  learning project; it resets on restart and is not shared across instances.
- Existing authentication, workspace roles, permissions, notifications,
  realtime updates and frontend functionality were left in place.

Verification

- All server JavaScript files passed `node --check` syntax validation.
- Dependency installation and database-backed API tests were not run in this
  environment, so live endpoint behaviour still needs to be tested locally.
